1. Pods 🛶
  Smallest deployable unit, wraps one or more containers.
  Containers inside a Pod share network and storage.

2. Deployments 📦
  Manage multiple replicas of Pods.
  Handle rolling updates and rollbacks.

3. Services 🌐
  Provide stable networking to Pods.
  Types: ClusterIP (internal), NodePort, LoadBalancer, ExternalName.

4. ConfigMaps & Secrets 🔑
  Store configuration and sensitive data separately from code.
  Inject into Pods as environment variables or mounted files.

5. Namespaces 🗂
  Logical isolation of resources in a cluster.
  Useful for separating environments (dev, staging, prod).

6. Ingress 🚪
  Routes external HTTP/HTTPS traffic into cluster services.
  Supports host/path-based routing.

7. Volumes & Persistent Volumes 💾
  Provide persistent storage beyond Pod lifecycle.

8. Auto-scaling 📈
  Horizontal Pod Autoscaler (HPA) to scale based on CPU/memory metrics.

9. Probes 🩺
  Liveness Probe → checks if container is healthy.
  Readiness Probe → checks if container is ready to serve traffic.

10. RBAC (Role-Based Access Control) 🛡
  Controls who can do what in the cluster.


💡 As a developer, the most used combo is:
  Deployment + Service + ConfigMap/Secret + Ingress + HPA + Probes


✅ You already know the key building blocks
  Workloads: Pods, Deployments
  Networking: Services, Ingress
  Configuration & Security: ConfigMaps, Secrets, RBAC
  Storage: Volumes, Persistent Volumes
  Scaling & Health: Auto-scaling, Probes
  Management & Packaging: Namespaces, Helm, CI/CD


🔍 Extra features worth learning after this (for advanced control & optimization)
  StatefulSets → For managing apps that need stable network IDs and storage (e.g., databases).
  DaemonSets → Run a Pod on every node (e.g., for monitoring agents or logging tools).
  Jobs & CronJobs → For one-time tasks or scheduled jobs.
  NetworkPolicies → Control how Pods communicate with each other for better security.
  PodSecurityStandards (PSS) → Built-in Kubernetes security rules for Pods.
  Resource Requests & Limits → Control how much CPU/memory Pods can use.
  Custom Resource Definitions (CRDs) → Extend Kubernetes with your own types and controllers.
  Operators → Automate app-specific management (like database scaling or backups).





Practice Plan
  Pods → Create and run your first Pod, understand its lifecycle.
  Deployments → Scale Pods, update them, and roll back changes.
  Services → Expose Pods inside the cluster and to the outside world.
  Ingress → Route external traffic to different services using paths/hosts.
  ConfigMaps & Secrets → Inject configuration and sensitive data into Pods.
  Namespaces → Organize and isolate resources.
  Volumes & Persistent Volumes → Store data that survives Pod restarts.
  Auto-scaling (HPA) → Scale Pods automatically based on load.
  Probes → Add health checks to ensure reliability.
  RBAC → Control user permissions in the cluster.
