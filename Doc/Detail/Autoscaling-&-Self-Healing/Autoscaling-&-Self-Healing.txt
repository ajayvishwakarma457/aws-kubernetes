🤖 Autoscaling & Self-Healing in Kubernetes

  1. Autoscaling
      Kubernetes can automatically add or remove Pods based on load (like CPU or memory usage).
          Horizontal Pod Autoscaler (HPA) → changes the number of Pods.
            Example: scale from 2 → 5 pods when CPU > 70%.
          Cluster Autoscaler (on cloud) → adds/removes worker nodes if the cluster itself runs out of capacity.
      👉 This means your app can handle traffic spikes without you manually scaling.


==============================================================================================================================================================

2. Self-Healing
  Kubernetes constantly watches the state of your apps.
    If a Pod crashes, K8s restarts it.
    If a Pod is unhealthy (failing health checks), it’s replaced automatically.
    If a Node dies, K8s reschedules Pods to another Node.
  👉 This ensures your app is always running and matches the desired state you declared.


==============================================================================================================================================================

✅ Simple Example

  You declare:
    “I want 3 replicas of my app.”
  If 1 Pod crashes → Kubernetes spins up a new one. (self-healing)
  If traffic grows → HPA scales Pods from 3 → 6. (autoscaling)
  If traffic drops → HPA scales back down to save resources.


==============================================================================================================================================================

📌 Summary for Docs

  Autoscaling = automatically adjusting the number of Pods (or nodes) to handle load.
  Self-Healing = Kubernetes restarts or replaces failed Pods/nodes to keep apps healthy.
